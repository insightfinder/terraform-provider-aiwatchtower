# aiwatchtower_model (Resource)

Manages an AI WatchTower model. A model is identified by the (user_name, model_name, model_version) triple.

## Example Usage

```terraform
# Copyright (c) InsightFinder Inc.
# SPDX-License-Identifier: MPL-2.0

# Minimal model: no data sources, nothing provisioned in UIE.
resource "aiwatchtower_model" "basic" {
  model_name    = "Fraud-Guard"
  model_version = "V1.0.0"
  model_type    = "OpenAI"
}

# Model with data sources. Each entry makes AI WatchTower create a UIE project named
# "<model_name>-<model_version>-<name>", so "name" must be a SHORT LABEL, not an
# existing project name — passing a full project name produces a doubled prefix
# (Fraud-Guard-V1-0-0-Fraud-Guard-V1-0-0-OutputLog) that resolves to nothing.
resource "aiwatchtower_model" "full" {
  model_name    = "Fraud-Guard"
  model_version = "V2.0.0"
  model_type    = "OpenAI"

  environment = "Production"
  description = "Fraud detection model, second generation"

  data_sources = [
    {
      name        = "InputLog"
      data_type   = "Log"
      data_source = "Custom"
    },
    {
      name        = "OutputLog"
      data_type   = "Log"
      data_source = "Custom"
    },
  ]

  ubl_dimension = 128
}

output "model_id" {
  value = aiwatchtower_model.full.model_id
}

# Monitors attached to the model are read-only here; they are managed outside this resource.
output "attached_monitors" {
  value = aiwatchtower_model.full.monitor_info
}
```

## Schema

### Required

- `model_name` (String) Name of the model.
- `model_type` (String) Model type identifier (for example 'OpenAI', 'Regression' or 'Classification'). Valid values come from the backend's configurable built-in and custom model type lists.
- `model_version` (String) Version of the model. Changing this renames the version in place — the backend moves the model record, its mapping relation and its monitors — rather than replacing the resource.

### Optional

- `data_sources` (Attributes List) Data sources to provision for this model. Each entry causes AI WatchTower to create a UIE project asynchronously after apply returns. (see [below for nested schema](#nestedatt--data_sources))
- `description` (String) Free-form description of the model.
- `environment` (String) Environment label for the model, for example 'Production'.
- `ubl_dimension` (Number) Dimension of the model's UBL (unsupervised baseline learning) setting.
- `user_name` (String) Owning AI WatchTower user. Defaults to the provider's username.

- `anomaly_count` (Number) Number of anomalies currently recorded against the model.
- `id` (String) Identifier for the model (user_name@model_name@model_version).
- `model_id` (String) Backend-generated model identifier.
- `monitor_info` (Attributes List) Monitors attached to this model. Read-only — monitors are managed outside this resource. (see [below for nested schema](#nestedatt--monitor_info))

## Import

Import is supported using the following syntax:

```shell
# Models are imported as user_name@model_name@model_version. The identifier is split from the
# right, so a user name that is an email address imports correctly.
terraform import aiwatchtower_model.example 'user@company.com@Fraud-Guard@V1.0.0'
```

## Notes

- **`data_sources[].name` is a suffix, not a project name.** AI WatchTower derives the UIE project
  name as `sanitize("<model_name>-<model_version>-<name>")` and does not check the result against
  UIE. Supplying an already-qualified project name therefore yields a doubled prefix such as
  `Fraud-Guard-V1-0-0-Fraud-Guard-V1-0-0-OutputLog`, which resolves to nothing: every downstream
  call 204s and monitors become uncreatable. The backend's `existInUIE` flag, which is the only
  way to reach that code path, is intentionally not exposed by this resource.

- **Project provisioning is asynchronous.** Creating or updating a model with new `data_sources`
  only enqueues a setup payload; a background consumer creates the UIE projects, adds them to a
  system and writes the mapping rows. A successful apply means the model record exists, not that
  its projects are ready. The resource emits a warning when it enqueues this work.

- **Changing `model_version` does not replace the resource.** The provider sends the previous
  version as the backend's `oldModelVersion`, which triggers an in-place rename: the model record,
  its mapping relation and its monitors all move, and the backend issues a fresh `model_id`.
  Changing `model_name` or `user_name` does force replacement.

- **Deleting a model that is already gone is not an error.** The backend reports success only when
  every key in a delete request was removed, so deleting an absent model fails the whole call. The
  provider re-reads the model after a failed delete and treats "not found" as success, which keeps
  `terraform destroy` working after someone has removed the model by hand.
